Poolula Platform — Demo Mode

A fully fictional dataset that drives the entire platform, safe to show anyone. Hand-off & walkthrough reference · July 2026

Data safety. Everything on screen in demo mode is invented — address, prices, trust, banks, insurance, guests, every dollar. Only the company name is real (client-approved). The demo runs on its own database (demo/demo.db) and vector store (demo/chroma_db/); real data is never read or written.

What was built

PieceWhereWhat it does
Demo factsdemo/demo_facts.yml Fictional twin of the real source-of-truth YAML; seeds the property.
Synthetic bookingsdemo/airbnb_demo_2024-12_2025-11.csv 58 fictional stays with Colorado ski-season seasonality, in the exact 22-column Airbnb export format. Generated deterministically by scripts/generate_demo_airbnb.py --seed 42.
Ground truthdemo/ground_truth.json True aggregates, computed from the CSV by the evaluator's own parser — eval numbers match by construction.
RAG corpusdemo/documents/ (5 markdown docs) Formation, insurance, compliance, accounting, and banking docs, all consistent with the facts YAML.
Eval setdemo/demo_eval_set.jsonl 20 questions mirroring the real chatbot eval set, expectations tied to the fiction.
Fixturesdemo/fixtures/ Recorded LLM responses — the whole eval suite replays offline with zero credentials.
Orchestratorscripts/setup_demo.sh One command builds the demo environment end-to-end; idempotent.
Teststests/test_demo_data.py Pins generator ↔ CSV ↔ ground truth ↔ eval set to each other; guards real-data backward compatibility.

How it fits together

1 · Seedsdemo_facts.yml · generated Airbnb CSV · 5 markdown docs
2 · Loadseed_database.py --facts · import_airbnb_transactions.py · ingest_documents.py
3 · Storesdemo/demo.db (SQLite) · demo/chroma_db (vectors)
4 · ServeFastAPI + RAG chatbot, switched by two env vars
5 · Proveevaluators score answers against ground_truth.json; fixtures replay offline

The entire real↔demo switch is two environment variables — no config framework, no demo flags in business logic:

DATABASE_URL=sqlite:///demo/demo.db
POOLULA_CHROMA_PATH=demo/chroma_db

Run it

SETUPBuild the demo environment

bash scripts/setup_demo.sh            # create / refresh (idempotent)
bash scripts/setup_demo.sh --reset    # wipe demo DB + vectors, rebuild

SERVEAPI + chatbot on fictional data

DATABASE_URL=sqlite:///demo/demo.db POOLULA_CHROMA_PATH=demo/chroma_db \
    uv run uvicorn apps.api.main:app --port 8082

Good live-demo queries: “Who insures the property and when does the policy renew?” · “What was my rental income in July 2025?” · “Who is the sole member of Poolula LLC?”

Talking points

  • Accrual accounting, verified end-to-end. Revenue recognizes at guest checkout, service fees at payout — importer and ground-truth calculator implement the same rule, so numeric eval assertions validate the whole pipeline, not just the LLM.
  • Ground truth by construction. The generator computes expected numbers with the evaluator's own parser; a test pins CSV, ground truth, and eval set together, so eval drift fails CI.
  • Record/replay evaluation. Clone the repo, replay the fixtures, read the diagnostic failure report — zero credentials required.
  • Deliberately simple. Two env vars switch environments; deterministic seeded generation instead of a faker dependency; no repository layers (KISS, sized for a 1-user platform).
